# TurboModules with Swift

## Why Swift Cannot Implement TurboModules Directly

TurboModules use JSI (JavaScript Interface), which operates at the C++ layer. Swift cannot interop with C++ directly — it needs Objective-C++ (`.mm` files) as a glue layer between Swift and the JSI runtime.

The architecture is:

```
TypeScript (Codegen spec)
    ↓
C++ generated header (NativeMyModuleSpec.h)
    ↓
Objective-C++ (.mm) — implements the TurboModule protocol
    ↓
Swift class — holds the actual business logic
```

---

## The `.mm` File Requirement

Objective-C++ (`.mm`) files can call both Objective-C and C++ APIs. This makes them the only viable bridge between the JSI-generated C++ spec and your Swift implementation.

Your Swift class does the real work. The `.mm` file wires it to the TurboModule system:

```objc
// NativeStorageModule.mm
#import "NativeStorageModule.h"
#import <React/RCTUtils.h>
#import "MyApp-Swift.h"  // auto-generated by Xcode — imports your Swift class

@implementation NativeStorageModule

RCT_EXPORT_MODULE()

- (std::shared_ptr<facebook::react::TurboModule>)getTurboModule:
    (const facebook::react::ObjCTurboModule::InitParams &)params {
  return std::make_shared<facebook::react::NativeStorageModuleSpecJSI>(params);
}

@end
```

## Swift-to-ObjC Bridging Header Setup

Xcode auto-generates `MyApp-Swift.h` when your project has a bridging header. To expose your Swift class to the `.mm` file:

1. In Xcode, go to **Build Settings** → search for **Objective-C Bridging Header**
2. Set it to `MyApp/MyApp-Bridging-Header.h` (Xcode usually creates this automatically on first Swift file)
3. The generated `MyApp-Swift.h` is imported in `.mm` files as shown above — no manual configuration needed

Your Swift class must be annotated with `@objc` or `@objcMembers` to be visible across the boundary:

```swift
// NativeStorageModuleSwift.swift
import Foundation

@objcMembers
public class NativeStorageModuleSwift: NSObject {
  private let queue = DispatchQueue(
    label: "com.myapp.storage",
    attributes: .concurrent
  )

  public func getItem(_ key: String) -> String? {
    return UserDefaults.standard.string(forKey: key)
  }

  public func setItem(_ key: String, value: String) {
    queue.async(flags: .barrier) {
      UserDefaults.standard.set(value, forKey: key)
    }
  }

  public func removeItem(_ key: String) {
    queue.async(flags: .barrier) {
      UserDefaults.standard.removeObject(forKey: key)
    }
  }
}
```

## Full End-to-End Example: NativeStorageModule

### 1. TypeScript Codegen spec

```typescript
// src/specs/NativeStorageModule.ts
import type { TurboModule } from 'react-native';
import { TurboModuleRegistry } from 'react-native';

export interface Spec extends TurboModule {
  getItem(key: string): string | null;
  setItem(key: string, value: string): void;
  removeItem(key: string): void;
}

export default TurboModuleRegistry.getEnforcing<Spec>('NativeStorageModule');
```

### 2. `package.json` Codegen config

```json
{
  "codegenConfig": {
    "name": "NativeStorageModuleSpec",
    "type": "modules",
    "jsSrcsDir": "src/specs",
    "android": {
      "javaPackageName": "com.myapp"
    }
  }
}
```

### 3. Objective-C++ header

```objc
// NativeStorageModule.h
#pragma once
#include <NativeStorageModuleSpec/NativeStorageModuleSpec.h>

@interface NativeStorageModule : NSObject <NativeStorageModuleSpec>
@end
```

### 4. Objective-C++ implementation

```objc
// NativeStorageModule.mm
#import "NativeStorageModule.h"
#import "MyApp-Swift.h"

@implementation NativeStorageModule {
  NativeStorageModuleSwift *_impl;
}

RCT_EXPORT_MODULE()

- (instancetype)init {
  if (self = [super init]) {
    _impl = [[NativeStorageModuleSwift alloc] init];
  }
  return self;
}

- (NSString *)getItem:(NSString *)key {
  return [_impl getItem:key];
}

- (void)setItem:(NSString *)key value:(NSString *)value {
  [_impl setItem:key value:value];
}

- (void)removeItem:(NSString *)key {
  [_impl removeItem:key];
}

- (std::shared_ptr<facebook::react::TurboModule>)getTurboModule:
    (const facebook::react::ObjCTurboModule::InitParams &)params {
  return std::make_shared<facebook::react::NativeStorageModuleSpecJSI>(params);
}

@end
```

## AppDelegate Changes

### Option A — `RCTAppSetupUtils` (recommended for RN 0.76+)

```objc
// AppDelegate.mm
#import <React/RCTAppSetupUtils.h>

@implementation AppDelegate

- (BOOL)application:(UIApplication *)application
    didFinishLaunchingWithOptions:(NSDictionary *)launchOptions {
  RCTAppSetupPrepareApp(application, YES); // YES = New Architecture
  // ...
  return YES;
}

@end
```

### Option B — Manual `RCTTurboModuleManagerDelegate`

Only use this when you need to intercept module creation (custom factories, testing overrides):

```objc
@interface AppDelegate () <RCTTurboModuleManagerDelegate>
@end

@implementation AppDelegate

- (Class)getModuleClassFromName:(const char *)name {
  return RCTCoreModulesClassProvider(name);
}

- (id<RCTTurboModule>)getModuleInstanceFromClass:(Class)moduleClass {
  return [moduleClass new];
}

@end
```

| Use | When |
|-----|------|
| `RCTAppSetupUtils` | Standard apps — handles New Architecture wiring automatically |
| Manual delegate | Custom module factories, test doubles, multi-window apps |

## Common Errors and Fixes

| Error | Root Cause | Fix |
|-------|-----------|-----|
| `NativeStorageModuleSpec.h: No such file or directory` | Codegen hasn't run yet | Run `pod install` after setting up `codegenConfig` in `package.json`; or run `./gradlew generateCodegenArtifactsFromSchema` for Android |
| `Type 'NativeStorageModule' does not conform to protocol 'NativeStorageModuleSpec'` | Method signature mismatch between spec and `.mm` | Check that method names and parameter types in the `.mm` exactly match the generated header |
| `Undefined symbol: _OBJC_CLASS_$_NativeStorageModuleSwift` | Linker cannot find Swift class | Ensure `@objcMembers` is on the Swift class and the `.mm` imports `MyApp-Swift.h` (not a manual header) |
| `Include of non-modular header inside framework module` | Mixing module and non-module headers | Add `s.pod_target_xcconfig = { 'DEFINES_MODULE' => 'YES' }` to the podspec |
